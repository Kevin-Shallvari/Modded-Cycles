# Free space, payloads and settings storage

Free space is scarce and every byte is accounted for. The source of truth is
`tweaks/model-cycles_OS1.13/REGISTRY.md`, generated by `python3 tools/registry.py` from the tweaks (notes/52).

## Freed sprite masks (default home for new code)

- Big `0xFF` blocks are sprite masks (`Bitmap`, ctor `0x40070172`, image +0x10, mask +0x14). Masks in a group are
  byte-identical; each is referenced only by the 32-bit constant passed to its constructor.
- `sprites.redirect_write(mask)` rewrites that constant to the group's kept copy: rendering is identical and the
  mask becomes free. The tweak that writes into a mask must include its redirect (or `requires` a tweak that does).
- `sprites.GROUPS`: 10 groups, 164 freeable masks, 104 to 1024 bytes. Sizes and which are free: `REGISTRY.md` §1.
  Never write into a kept copy (`registry.py` refuses).
- Big code is split over several masks (sample preview: four 47×47 masks) with one linker section per mask.
- Two mods may share a mask only if they are never built together (or one `requires` the other), or if they never
  write the same bytes when built together (trig-hold in front of 6ch-usbup's stubs in `0x4015c044`).
  `check_overlaps.py` proves it.
- Check open PRs before taking one: `python3 tools/registry.py --git origin/<branch>`.

## Other 0xFF caves

Writes into `0xFF` outside masks are refused by both builders when the stock image points into the zone, unless a
chosen tweak rewrites that pointer, or `device.json` lists it in `cave_refs_ok` (with `why` and a note). See
`REGISTRY.md` §2.

## Payload appended to the image (large code)

- Copied at boot to SDRAM by a boot hook: Syntakt engines and MACRO at `0x43000000` (notes/17, 50), Model-TG at
  `0x46700000` (notes/31). Tweak fields: `append` (+ `compress: "aplib"`, `stored`), chained payloads (`at`,
  `dest`); `check_overlaps.py` checks the chain, `build.END_LIMIT = 0x40200000` bounds the decompressed image.
- The boot hook is shared; a new payload user joins the existing chain rather than adding a hook. Read notes/50
  before touching it. `build.py` and `docs/flasher/builder.js` must read any new field identically.

## Data the mod keeps

- RAM state: BSS of the mod's own section (zero in the image), or proven-unused RAM above the OS BSS (lfo-plus:
  1 180 bytes, notes/56). Never a single global if the code is re-entrant.
- Settings that survive a save: unused bytes of the pattern/project/sound structures, **proven unused** (arp uses
  pattern track byte +512, notes/32 §4; track-filter uses sound slots 18, 27, 30, 31, notes/47). Declare them in
  `DECLARED` of `tools/registry.py` with the proving note. Two mods claiming the same bytes must `conflict`
  (lfo-plus vs track-filter).
- Settings written to the global settings block (`0x404e9b10`) need the checksum recomputed (notes/53).
