# Web flasher integration

The page builds ONE firmware, the Modded Cycles OS, in the browser from the user's own official files and sends it
over Web MIDI. There is nothing to tick: step 1 is a read-only list of what the OS contains. Static files, no build
step, must work from `file://` and on GitHub Pages; users' files never leave the browser.

```
os.json                  THE OS: name, version, status, ordered tweak ids, machines (MACHINES menu order), features
docs/flasher/app.js      UI: FEAT texts en/fr, REF_MAINOS + REF_MODS (generated blocks), the OS header and rows, flashing steps
docs/flasher/builder.js  port of tools/build.py + mtlib (must stay byte-identical)
docs/flasher/flasher.js  .syx checks, Web MIDI (classic CONFIG › UPGRADE, fast Transfer protocol, notes/37)
docs/flasher/tweaks.js   GENERATED by tools/gen_flasher_tweaks.py from os.json + tweaks/; never edit by hand
```

## Putting a tweak into the OS (in this order)

1. The tweak is proven alone and `--with` the other tweaks of `os.json`, `tools/check_overlaps.py` passes with it,
   it declares no `conflicts` with a tweak of the OS and its `requires` are in the OS (skill `emulation-proofs`,
   `tweak-generators`). If not, it does not enter: solve the conflict first.
2. `os.json`: add the tweak id to `"tweaks"` (build order is by the tweak's `order`, the list order is the
   `REF_MAINOS` key), and a feature to `"features"`: `id`, `cat` (`sound`, `seq`, `live`, `screen`, `io`),
   `tweaks` (the ids it owns; `[]` for a feature that rides inside another tweak), `"status": "experimental"`,
   `credit` (`null` or `{"kind": "by"|"based", "who", "repo"?}`), `license` when it carries outside code
   (file in `tweaks/model-cycles_OS1.13/`), `guide` (the guide section id), `notes`. A new machine goes into
   `"machines"` at its place in the MACHINES menu. Set the OS `"status"` back to `"experimental"`: its composition
   changed.
3. `python3 tools/gen_flasher_tweaks.py` → `docs/flasher/tweaks.js` and the license files the page serves; then
   `--check`. It refuses an unbuildable OS, an unknown tweak, an unowned tweak, a bad category.
4. `python3 tools/ref_mainos.py --cycles firmware/model-cycles_OS1.13.syx --syntakt firmware/Syntakt_OS1.42.syx`
   rewrites `REF_MODS` (hash of each tweak's writes `w` and payload `p`) and `REF_MAINOS` (the MAIN OS of the OS,
   one key) in `app.js`. Never edit those blocks or resolve merge conflicts in them by hand: rerun the script.
   `python3 tools/build.py … --os` prints the same MAIN OS SHA-256; put it in `BUILD.md`.
5. `docs/flasher/app.js`, `FEAT.en["<id>"]` and `FEAT.fr["<id>"]` (same keys): `label`; `short` (~100 chars, what
   it does on the machine, with its key combination); `desc` (the Details drawer, full text); optional `note`
   (shown in Details under "Before installing"), `parts` (a big feature: what it brings, one line);
   `"eng-<code>"` shorts for Syntakt engines; `"mach-<code>"` labels for added machines. Texts follow
   `bilingual-user-docs` (musicians, buttons, limits, no addresses; French « vous »). The guide anchor comes from
   `os.json` (`guide`), not from app.js.
6. `tools/webflash_smoke.js`, section 1: the expected tweak list (`ids`), the row order by section
   (`feats.join()`), the credit links count, the French-row checks. Section 6 builds the OS from the real files.
7. Run `tools/webflash_smoke.sh` (synthetic), then with the real files (the OS built in the page, each tweak
   checked against `REF_MODS`, the MAIN OS against `REF_MAINOS`).

## Taking a tweak out, or a status change

- Out of the OS: remove it from `"tweaks"` and `"features"` (and `"machines"`), steps 3 to 7 again, release entry
  and `FEATURES.md` ("Outside the single OS, and why"). The tweak stays in `tweaks/` as a library entry unless the
  project drops it entirely.
- After a hardware test: `"status": "tested"` on the feature in `os.json` (and on the OS itself when Maxime tested
  this exact firmware), regenerate `tweaks.js`, then the guide's *Tested* line, `FEATURES.md`, a release entry,
  the stamp (skill `hardware-test-handoff`). `.github/scripts/discord.mjs` reads the feature statuses of
  `tweaks.js` to announce changes.

## Invariants

- `builder.js` ≡ `tools/build.py`: a change to how one reads a tweak goes into the other in the same commit
  (`tools/webbuild_check.sh`). `flasher.js` validates `.syx` like `tools/mtlib/syx.py` (`tools/webflash_check.sh`).
- The OS keeps `CONFIG › UPGRADE` over USB working; `6ch-multiout`, `sdvintage-snare`, `sdvintage-exact` stay
  command-line only.
- The OS needs the Syntakt file as long as it carries the Syntakt engines: the page asks for it in step 2 and the
  Details of the engines row say so (`needs: "syntakt"` on the feature).
- No `fetch` of local files (that is why `tweaks.js` embeds the JSON); relative script paths.
- Bump the `?v=` / `MC_BUILD` stamp whenever a page or script changes (skill `bilingual-user-docs`).
- The home page list (`ol.mods` in `docs/index.html`) is a short selection of the OS: add an item only if Maxime asks.
- A Model:Samples gets the same OS (`MCBuilder.modsForSamples`, notes/57): nothing to do per feature.
